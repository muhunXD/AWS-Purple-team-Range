# T1098.001 — Additional Cloud Credentials

Catches an access key being created on an IAM user other than the caller, which is how
an attacker keeps a way back in.

Detonated `2026-08-20 14:09:57 UTC` in `us-east-1` using
`aws.persistence.iam-backdoor-user`.

```
fields @timestamp, eventName, userIdentity.userName, requestParameters.userName, userIdentity.arn, sourceIPAddress
| filter eventName = "CreateAccessKey"
| sort @timestamp desc
| limit 50
```

Normally a person creates an access key for themselves, so the caller and the target
user are the same. The interesting case is when they differ. In the detonation the
caller was my SSO admin session and `requestParameters.userName` was
`malicious-iam-user`, so a key was minted on an identity the caller does not own.

| Detonation window | Clean window |
|---|---|
| Fired — key created on `malicious-iam-user` | Did not fire |

This one has real false positives. Admins create keys for other users all the time
during onboarding or when setting up service accounts, and that looks identical in
CloudTrail. So this is a detection that flags for review rather than something that
should ever auto-block. In a real SOC it would be correlated against a change ticket or
an approved user list.

Because IAM is global these events land in `us-east-1` even though the range runs in
`ap-southeast-7`, which is a good check that the multi-region trail is working.
