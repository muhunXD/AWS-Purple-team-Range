# T1562.008 — Impair Defenses: Stop CloudTrail

Catches any attempt to stop, delete or reconfigure a CloudTrail trail, whether it
succeeds or is blocked.

Detonated `2026-08-20 10:33:11 UTC` in `ap-southeast-7` using
`aws.defense-evasion.cloudtrail-stop`.

```
fields @timestamp, eventName, errorCode, userIdentity.arn, sourceIPAddress
| filter eventName in ["StopLogging","DeleteTrail","UpdateTrail","PutEventSelectors"]
| sort @timestamp desc
| limit 50
```

These four API calls should basically never happen during normal operation, so any
occurrence is worth an alert. In this environment they are also denied by the
`deny-cloudtrail-tampering` SCP, which means the event arrives with
`errorCode: AccessDenied`. That turns out to be useful rather than a problem — the
denial proves prevention worked, and the event still proves detection would have worked
if it had not.

| Detonation window | Clean window |
|---|---|
| Fired — `StopLogging` with `AccessDenied` | Did not fire |

This is the cleanest of the five detections. Legitimate trail changes are rare and
planned, so the false positive rate is close to zero. The one thing to watch is that a
planned trail change by an administrator would also fire it, which is acceptable for
something this sensitive.

Worth noting the same SCP later denied `DeleteTrail` when Stratus tried to clean up its
own warmup trail, which is captured separately in `evidence/scp-findings.md`.
